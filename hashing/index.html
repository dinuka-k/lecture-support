      Using the hashing demo

      The four modes

      • Hash table: h(k) = k mod m picks a slot. Collisions are resolved by chaining (a list per bucket) or open addressing: linear probing, quadratic probing or double hashing. Deleting in open addressing leaves a "deleted" marker. Turn on auto-rehash to grow the table when the load factor α = n/m passes 0.75.
      • Disk hash index: static hashing: N buckets, each a disk page with overflow pages. An equality lookup costs about one page read; a range query must read every page, because hashing scatters neighbouring keys.
      • Extendible hashing: a directory of 2d pointers indexed by the last d bits of the hash. A full bucket splits; if its local depth equals the global depth, the directory doubles first.
      • Linear hashing: no directory: buckets split one at a time in round-robin order, pointed to by next. An overflow anywhere triggers the split of bucket next. Buckets before next use hlevel+1.

      Try this

      • Press Example in each mode, then insert the suggested keys.
      • In the hash table, compare linear and quadratic probing on the same keys, watch the clusters.
      • In the disk index, run Range with 10-30 and count the page reads.

      Notes

      • Keys are whole numbers 0–99. Every mode keeps its own keys and timeline, so you can switch back and forth.
      • The hash function is kept simple (k mod m, or the key's own bits) so the arithmetic can be followed on the board.
      • Extendible hashing uses the last d bits (as in Ramakrishnan & Gehrke); some books use the first bits, the idea is the same.
