    How a query optimizer decides
    
      
    
        
    
          
    The pipeline
    
          
      
            
    • Parser: checks the grammar, splits the SQL into clauses and binds every name to the catalog. The result is the canonical tree π(σ(R₁ × R₂ × …)), correct but very slow.
      • 
            
    • Rewriter (rule-based, RBO): applies equivalence rules in a fixed order, unnest subqueries, fold constants, remove redundant or impossible conditions, split AND, push selections down, turn × + condition into ⋈, infer transitive conditions, prune columns. Rules don’t look at data sizes.
      • 
            
    • Planner (cost-based, CBO): uses statistics (rows, pages, distinct values, min/max, indexes) to estimate how many rows each step produces and what it costs. It chooses an access path per table (Seq Scan or Index Scan), the join order (dynamic programming over sets of tables) and a join method (nested loop, index nested loop, hash, merge).
      • 
          
    
          
    Simplifications
    
          
      
            
    • The cost formulas are a simplified version of PostgreSQL’s (sequential page 1.0, random page 4.0, per row 0.01, per comparison 0.0025). Real systems also count memory, caching and “interesting orders”.
      • 
            
    • Selectivity uses uniform distributions and assumes filters are independent; there are no histograms.
      • 
            
    • Joins are inner joins; outer joins, HAVING, NULLs and correlated subqueries are not covered.
